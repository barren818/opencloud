```

            ├─ Nginx 1.21.5 :80 ── /company/website/html（宿主机版网站）
```

## 四、部署细节摘要

### 存储（LVM）
- `company_vg`：project_lv 7G → /company-data；website_lv 8G → /website-data；backup_lv 4G → /backup-data；ext4，fstab 自动挂载（阶段六案例 06 验证过重启后自动挂载恢复）。
- project_lv 两次扩容：方案 5G→6G；阶段六案例 04 因大文件占满再扩至 7G（lvextend + resize2fs 在线扩容）。

### 网站（Nginx）
- 宿主机版：Nginx 1.21.5，:80，根目录 /company/website/html，index.html 约 556 字节（含阶段八追加的 `<!-- v2 -->` 注释）；Windows 浏览器访问 200 已验证；access_log / error_log 改道至 /company/website/logs。
- 容器版：Podman 3.4.4，镜像 nginx:latest（经 DaoCloud 源 `docker.m.daocloud.io` 拉取，镜像内 nginx 1.31.9），容器 `nginx-web`，`-p 8080:80 -v /opt/webhtml:/usr/share/nginx/html:ro,Z`；:8080 浏览器验收通过。
- SELinux 保持 Enforcing：网站目录打 `httpd_sys_content_t`、日志目录打 `httpd_log_t`，均用 semanage + restorecon 正规修复，未关闭 SELinux、未用 chmod 777。

### 安全（阶段九）
- SSH：root 只许密钥登录（`PermitRootLogin prohibit-password`），全机关闭密码登录（`PasswordAuthentication no`）；Ed25519 密钥对，公钥 1 行装入 authorized_keys；双向实测通过（带钥匙免密进、无钥匙直接被拒）。
- 防火墙：放行收敛为 `dhcpv6-client http ssh`（已移除 mdns）；443 待 HTTPS 后再开。阶段十一另永久放行 8080/tcp，供容器网站对外服务。
- 审计：近期登录全为 root、来源仅 192.168.6.1 与 tty1；Failed / Invalid 登录零条。

### 资源（阶段十，2026-11-19 09:35–09:46 采样）

## 六、故障排查手册（7 个案例，超额完成）

阶段十二最低要求 5 个，实际 7 个。详见 `故障排查手册.md`。

| # | 故障 | 一句话原因 | 处置要点 |
|---|---|---|---|
| 01 | Nginx 停服，curl Connection refused | 服务未运行，80 无监听 | systemctl start nginx |
| 02 | 改根目录后 Nginx 403 | SELinux 标签 default_t | semanage 打 httpd_sys_content_t + restorecon |
| 03 | DNS 解析失败 | resolv.conf 被改坏为 192.0.2.1 | 还原备份的 resolv.conf |
| 04 | /company-data 占至 96% | 5.3G 测试大文件 | lvextend +1G 在线扩容，再删测试文件 |
| 05 | Nginx 启动失败 | conf.d/broken.conf 含非法指令 | 删坏配置，nginx -t 通过后重启 |
| 06 | 重启后 /website-data 未挂载 | fstab 该行被注释 | 去注释 + daemon-reload + mount -a，二次重启验证 |
| 07 | 容器 :8080 外部访问挂起 | 端口发布层僵死（conmon 监听但不转交） | 停删容器后按原命令重建；数据在挂载卷中不受影响 |

排障方法论（本项目沉淀）：先分层定界（服务→日志→监听者→直连本体），再动手；容器坏了优先按原参数重建，不逐行修内部状态。
