# 阶段九 · 安全审查清单（SSH / 防火墙 / 登录审计）

**审查对象**：openEuler 22.03 LTS SP4 虚拟机（ens33 = 192.168.6.135，NAT）
**审查时间**：2026-11-18 ～ 2026-11-19
**审查人**：root（本机运维）

---

## 一、SSH 策略（任务 1）

整改前生效值（`sshd -T`）：`port 22`、`permitrootlogin yes`、`passwordauthentication yes` —— root 可凭密码直接远程登录，为本次整改对象。

整改动作：
- 改前备份：`/etc/ssh/sshd_config.bak.2026-11-18`
- VMware 控制台 root 本地登录先行验通（应急通道）；现有 MobaXterm 会话全程保留
- Windows 侧生成 Ed25519 密钥对，私钥留本机；公钥装入 `/root/.ssh/authorized_keys`（`.ssh` 权限 700、`authorized_keys` 权限 600，公钥恰好 1 行）
- 先验密钥登录：新会话免密进入，`journalctl -u sshd` 实锤 `Accepted publickey for root from 192.168.6.1`（ED25519，匹配 authorized_keys 第 1 行）
- 改配置（主文件，无 sshd_config.d 分文件）：第 41 行 `PermitRootLogin yes` → `prohibit-password`，新增 `PasswordAuthentication no`；`sshd -t` 静默通过，重启 sshd 无报错

整改后生效值（`sshd -T` 复验）：
- `permitrootlogin without-password`（即 prohibit-password，老叫法同效）—— root 只许密钥登录
- `passwordauthentication no` —— 全机密码登录关闭
- `pubkeyauthentication yes`、`port 22` 不变

双向实测（2026-11-19）：
- 带私钥新会话：免密落进提示符 ✅
- 无私钥会话：被拒，服务器回 `No supported authentication methods available (server sent: publickey,gssapi-keyex,gssapi-with-mic)` —— 认证方式清单中已无 password ✅

## 二、防火墙与端口清单（任务 2）

对账方法：`firewall-cmd --list-all`（放行面）与 `ss -tlnp`（实际监听）逐项核对。

| 端口 | 服务/进程 | 防火墙 | 处置 | 理由 |
|---|---|---|---|---|
| 22/tcp | sshd | ssh 放行 | **保留** | 远程管理通道；已改为仅密钥认证 |
| 80/tcp | nginx | http 放行 | **保留** | 企业网站对外服务 |
| 443/tcp | —（无监听） | 未放行 | **暂不开** | 待后续配置 HTTPS 后再开放 |
| 5353/udp | mdns | 原默认放行 | **已移除** | 局域网设备发现，服务器无此需求；`firewall-cmd --permanent --remove-service=mdns` + `--reload` 后生效 |
| — | dhcpv6-client | 放行 | **保留** | 本机作为 DHCPv6 客户端接收地址配置，非对外服务，发行版默认 |

实际监听（`ss -tlnp`）仅 sshd（22）与 nginx（80），IPv4/IPv6 双栈；无未知进程监听。防火墙现放行服务：`dhcpv6-client http ssh`。

## 三、登录审计（任务 3）

- `last` 近期记录：全部为 root，来源只有两个 —— `192.168.6.1`（Windows 宿主机，SSH）与 `tty1`（VMware 控制台本地登录）；无陌生 IP、无其他用户登录。
- `journalctl -u sshd | grep -E "Failed|Invalid"`：**零条** —— 无密码爆破、无非法用户名试探痕迹（本机位于 NAT 内网、未对公网暴露，与此结果吻合）。
- 备注：`last` 中个别会话以 `crash` 结束，为虚拟机直接关机所致，非异常。

## 四、结论与后续

- 本机对外攻击面收敛为 22（仅密钥）+ 80（网站）两项必要服务，SSH 已完成密钥化加固，登录审计无异常。
- 后续事项：配置 HTTPS 后再开放 443；私钥文件需在 Windows 侧妥善保管（丢失时用 VMware 控制台通道补装新公钥）；本清单纳入阶段十二交付报告。
